# fieldseal-adapters-html

## Overview

Draws a render plan as one self-contained HTML page: the platform adapter behind `fieldseal instrument preview` (ADR 0033, INS-208; see [0033-presentation-layouts.md](../../../docs/explanation/adr/0033-presentation-layouts.md) and [instrument.md](../../../docs/reference/spec/instrument.md)). The page is faithful to the plan: every node is drawn in plan order and none is regrouped, reordered or left out, except nodes that resolved visibility hides. The adapter decides only how each node kind looks.

Layer: adapter. Depends on `fieldseal-kernel` and `fieldseal-instrument` (plan, instrument, CLDR locale data). It implements no context port: it is a pure rendering function.

| Plan node | Drawn as |
| --- | --- |
| `step`, `review` | A section per step behind a stepper; the review lists every answer |
| `tabs`, `tab` | The ARIA tabs pattern |
| `card`, `group` | A bordered card with its heading |
| `row` | A grid, side by side on wide windows, stacked on compact ones |
| `list`, `instance` | One card per instance |
| `table`, `instance` | A real `<table>`, one row per instance |
| `question` | A labelled control; coded controls are a `fieldset` with a `legend` |
| `display` | Text styled by role |

## Interface

- `render_html(&Page<'_>) -> String`: deterministic; the same page gives the same bytes.
- `Page<'a> { plan, instrument, visibility, values, roster, fingerprint }` and `Page::new(plan, instrument)` (no values, every node visible, nothing selected).
- `STYLE: &str` (the inline style sheet: `fonts.css` followed by `page.css`) and `SCRIPT: &str` (`page.js`).
- `Segment { Literal(String), Variable(String) }` and `segments(message, value, plural) -> Vec<Segment>`: cuts a MessageFormat 2 subset message (INS-084) into literals and variable placeholders, choosing a `.match` variant.

Private modules: `render` (page drawing), `escape` (text and attribute escaping, base64), `strings` (built-in navigation text per language, English fallback), `message`. Non-code assets in `src/`: `page.css`, `page.js`, `fonts.css` (generated by `tools/build-adapter-font.sh`; do not edit). `fonts/` holds the subset Nunito Sans woff2 files and `OFL.txt` (SIL OFL 1.1); they are embedded as `data:` URIs through `fonts.css`.

## Invariants

- Options and scale steps appear in the instrument's order with none selected unless a current value is supplied (INS-020, INS-021); nonresponse is shown as separate buttons, never options (INS-140); collector guidance only when the instrument is not self-administered (INS-151).
- Numbers, currencies, dates and plurals are formatted for the plan's language with CLDR data (INS-088); inputs show and accept the language's digits and separators, but stored values stay locale-free.
- Every instrument text is escaped and reaches the page only through the escape helpers, never inside `<script>` or `<style>`.
- The page makes no requests: style and script are inline and pinned by a `Content-Security-Policy` of their SHA-256 hashes (`default-src 'none'`, `form-action 'none'`); images are `data:` URIs; forms submit nowhere. Without the script every step and tab is shown.
- Text direction comes from the plan; the style uses logical properties so right-to-left plans mirror.
- `segments` shows anything it cannot read as literal text; variant ranking is exact match, then plural category, then `*`.

## Side Effects

- None at run time: no filesystem, network, clock or randomness. `STYLE` and `SCRIPT` are compiled in with `include_str!`.

## Verification

- Run: `cargo test -p fieldseal-adapters-html` (repo-wide: `just test`)
